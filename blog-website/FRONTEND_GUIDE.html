Building the frontend, step by step

This guide starts where the template stops.

Where you are now: the template is integrated. The 7 pages (Home, Articles, ArticleDetail, About, Login, Register, Dashboard) show the right design, the Tailwind theme is in index.css, and the routes work. But every page shows fake, hard-coded content. Nothing talks to the backend.

Where you are going: real posts from MongoDB, real accounts, and a dashboard where a writer can create, edit and delete their own posts.

We go from the bottom up: first the pieces that talk to the backend (types, services), then the pages that use them. Every step ends with a way to check that it works before you move on.

Keep the backend running (cd backend && npm run dev) the whole time.

Step 2 — Describe the data: types/

Before calling the api, write down what the api answers. Open backend/src/models/post.models.ts and copy the fields.

Create src/types/User.ts:

export interface User {
    _id: string;
    name: string;
    email: string;
}

// what POST /users/login sends back
export interface LoginResponse {
    user: User;
    token: string;
}

Create src/types/Post.ts:

// The author is populated by the backend, so it comes back as an object
export interface Author {
    _id: string;
    name: string;
    email: string;
}

export interface Post {
    _id: string;
    title: string;
    slug: string;
    tag: string;
    readTime: string;
    excerpt: string;
    body: string;
    quote?: string;
    image?: string | null;
    status: 'published' | 'draft';
    authorId: Author | string;
    createdAt: string;
    updatedAt: string;
}

Two details:

  • Dates are string, not Date. JSON has no date type.
  • authorId is Author | string. The list and byslug routes call .populate('authorId'), so you get an object. The mine route does not, so you get just the id.

Step 3 — One axios instance: services/api.ts

Every request goes through this file. We set the base url once, and we add the token automatically.

import axios from "axios";

const api = axios.create({
    baseURL: 'http://localhost:4000/api',
    timeout: 10000
})

// before every request, add the token if the user is logged in
api.interceptors.request.use((config)=>{

    const token = localStorage.getItem('token');

    if(token){
        config.headers.Authorization = `Bearer ${token}`;
    }

    return config;
})

export default api;

The backend's authenticate middleware reads Authorization: Bearer <token>. Thanks to the interceptor, you never write that header by hand.

Step 4 — The auth service: services/authService.ts

All the backend answers look like { success, message, data }, so the useful part is always response.data.data.

import api from "./api";
import type { User, LoginResponse } from "../types/User";

export const authService = {

    register: async ( data: { name: string, email: string, password: string } ) : Promise<User> =>{
        const response = await api.post('/users/register', data);
        return response.data.data;
    },

    login: async ( data: { email: string, password: string } ) : Promise<LoginResponse> =>{
        const response = await api.post('/users/login', data);
        const result: LoginResponse = response.data.data;

        // keep the token and the user in the browser
        localStorage.setItem('token', result.token);
        localStorage.setItem('user', JSON.stringify(result.user));

        return result;
    },

    logout: () : void =>{
        localStorage.removeItem('token');
        localStorage.removeItem('user');
    },

    // the user saved at login, or null when nobody is logged in
    getCurrentUser: () : User | null =>{
        const user = localStorage.getItem('user');
        return user ? JSON.parse(user) : null;
    },

    isLoggedIn: () : boolean =>{
        return localStorage.getItem('token') !== null;
    }
}

localStorage only stores strings. That is why we save the user with JSON.stringify and read it back with JSON.parse.

Step 5 — The post service: services/postService.ts

One function per backend route.

import api from "./api";
import type { Post } from "../types/Post";

export const postService = {

    // every published post, for the public blog
    getAll: async () : Promise<Post[]> =>{
        const response = await api.get('/posts/list');
        return response.data.data;
    },

    // one post, for the article page
    getBySlug: async (slug: string) : Promise<Post> =>{
        const response = await api.get('/posts/byslug/' + slug);
        return response.data.data;
    },

    // the posts of the logged in user, drafts included
    getMine: async () : Promise<Post[]> =>{
        const response = await api.get('/posts/mine');
        return response.data.data;
    },

    // we send FormData because a post can have a cover image
    create: async (data: FormData) : Promise<Post> =>{
        const response = await api.post('/posts/create', data);
        return response.data.data;
    },

    update: async (id: string, data: FormData) : Promise<Post> =>{
        const response = await api.put('/posts/edit/' + id, data);
        return response.data.data;
    },

    delete: async (id: string) : Promise<void> =>{
        await api.delete('/posts/delete/' + id);
    }
}

create and update take a FormData, not an object. An image file cannot go inside JSON. When axios sees a FormData it sets the multipart/form-data header by itself, so don't set it yourself.

Step 6 — Small helpers: services/helpers.ts

Two things every page needs:

// "2026-09-14T10:00:00.000Z"  ->  "Sep 14, 2026"
export const formatDate = (date: string) : string =>{
    return new Date(date).toLocaleDateString('en-US', {
        month: 'short',
        day: 'numeric',
        year: 'numeric'
    })
}

// the backend gives "/uploads/posts/post-123.jpg", the browser needs the full url
export const imageUrl = (image?: string | null) : string | null =>{
    return image ? 'http://localhost:4000' + image : null;
}

Note that the image url has no /api. app.ts serves /uploads directly.

Check (steps 2–6): nothing shows on screen yet, but npm run build must pass with no TypeScript errors.

Step 7 — Register page

We need an account before we can test anything else, so start here.

In pages/Register.tsx, above the component, write the form rules:

import { useNavigate } from "react-router-dom";
import { useForm } from "react-hook-form";
import { zodResolver } from "@hookform/resolvers/zod";
import { z } from "zod";
import Swal from "sweetalert2";
import { authService } from "../services/authService";

const registerSchema = z
  .object({
    name: z.string().min(2, "name must contain at least 2 characters"),
    email: z.string().email("invalid email"),
    password: z.string().min(6, "password must contain at least 6 characters"),
    confirmPassword: z.string(),
    terms: z.literal(true, { message: "you must accept the terms" }),
  })
  // the two passwords have to be the same
  .refine((data) => data.password === data.confirmPassword, {
    message: "the two passwords are different",
    path: ["confirmPassword"],
  });

type RegisterForm = z.infer<typeof registerSchema>;

Use the same limits as the backend (backend/src/schemas/user.schema.ts). The user sees the error right away, without a round trip to the server.

Inside the component:

const navigate = useNavigate();

const {
  register,
  handleSubmit,
  formState: { errors, isSubmitting },
} = useForm<RegisterForm>({ resolver: zodResolver(registerSchema) });

const onSubmit = async (data: RegisterForm) => {
  try {
    // the backend only needs these three
    await authService.register({ name: data.name, email: data.email, password: data.password });
    Swal.fire({ icon: "success", title: "Account created !", text: "You can sign in now." });
    navigate("/login");
  } catch (error: any) {
    Swal.fire({
      icon: "error",
      title: "Could not create the account",
      text: error.response?.data?.error || "Something went wrong",
    });
  }
};

Then connect the template's JSX:

  1. <form onSubmit={handleSubmit(onSubmit)}>
  2. on each input, add {...register("name")}, {...register("email")}, and so on. The name must match the schema.
  3. under each input, show the error: tsx {errors.email && <p className="...">{errors.email.message}</p>}
  4. on the submit button: disabled={isSubmitting}

Check: leave everything empty and click submit. You should see the red messages. Then fill the form correctly. You should land on /login, and the user should be in MongoDB (check with Compass).

Step 10 — Home page: load the posts

Every page that loads data uses the same 3 pieces of state and the same useEffect. Learn this pattern once and you have it for all the pages.

const [posts, setPosts] = useState<Post[]>([]);
const [loading, setLoading] = useState(false);
const [error, setError] = useState<string | null>(null);

useEffect(() => {
  const fetchPosts = async () => {
    try {
      setLoading(true);
      const data = await postService.getAll();
      setPosts(data);
      setLoading(false);
    } catch (err) {
      setLoading(false);
      setError("Failed to load the posts");
      console.log(err);
    }
  };

  fetchPosts();
}, []);   // [] -> only once, when the page opens

// the newest post goes in the big card, the next three go in the grid
const featured = posts[0];
const others = posts.slice(1, 4);

Now replace the fake content in the JSX:

{loading && <p>Loading...</p>}
{error && <div>{error}</div>}

{featured && (
  <Link to={`/articles/${featured.slug}`}>
    {featured.image && <img src={imageUrl(featured.image)!} alt={featured.title} />}
    <span>{featured.tag}</span>
    <h2>{featured.title}</h2>
    <p>{featured.excerpt}</p>
    <p>{formatDate(featured.createdAt)} &middot; {featured.readTime} read</p>
  </Link>
)}

{others.map((post) => (
  <Link key={post._id} to={`/articles/${post.slug}`}>
    {/* same idea: one card, the fields come from `post` */}
  </Link>
))}

{!loading && posts.length === 0 && <p>No posts yet.</p>}

The method: keep one card from the template, delete the copies, wrap it in .map(), and replace each hard-coded text with post.something. Keep all the classNames as they are.

If a post has no image, show the template's gradient block instead of <img>: {post.image ? <img .../> : <div className="brand-gradient ..."/>}.

Check: the blog is empty for now, so you should see "No posts yet". We fix that at step 13. If you are impatient, create a post with Postman.

Step 12 — Article detail: read the slug from the url

The route is /articles/:slug, so the slug is in the url:

const { slug } = useParams<{ slug: string }>();

const [post, setPost] = useState<Post | null>(null);
const [readNext, setReadNext] = useState<Post[]>([]);
const [loading, setLoading] = useState(false);
const [error, setError] = useState<string | null>(null);

useEffect(() => {
  const fetchPost = async () => {
    try {
      setLoading(true);
      setError(null);

      const data = await postService.getBySlug(slug!);
      setPost(data);

      // two other posts for the "Read next" section
      const all = await postService.getAll();
      setReadNext(all.filter((p) => p.slug !== slug).slice(0, 2));

      setLoading(false);
    } catch (err) {
      setLoading(false);
      setError("This post does not exist");
    }
  };

  fetchPost();
  window.scrollTo(0, 0);   // start at the top when we open another post
}, [slug]);   // run again when the slug changes (click on "Read next")

Why [slug] and not []? When you click a "Read next" link you stay on the same page component, only the slug changes. Without slug in the array the old post would stay on screen.

The body is one long text with one paragraph per line. Split it back:

const paragraphs = post ? post.body.split("\n").filter((line) => line.trim() !== "") : [];
const lede = paragraphs[0];        // the first one is shown bigger
const rest = paragraphs.slice(1);

// populated -> object ; not populated -> just the id
const authorName = post && typeof post.authorId === "object" ? post.authorId.name : "";

In the JSX:

{loading && <p>Loading...</p>}
{error && <h1>{error}</h1>}

{post && (
  <article>
    <h1>{post.title}</h1>
    <p>{authorName} &middot; {formatDate(post.createdAt)}</p>
    {post.image && <img src={imageUrl(post.image)!} alt={post.title} />}
    <p className="text-[22px] ...">{lede}</p>
    {rest.map((paragraph, index) => <p key={index}>{paragraph}</p>)}
    {post.quote && <blockquote>{post.quote}</blockquote>}
  </article>
)}

Check: click a card on Home. The right post opens, and the url shows its slug. Type a slug that does not exist in the url. You should see "This post does not exist".

Step 13 — The Dashboard

This is the biggest page. Build it in 6 small steps and test after each one.

13.1 Protect the page and load your posts

const navigate = useNavigate();
const user = authService.getCurrentUser();

const [posts, setPosts] = useState<Post[]>([]);
const [loading, setLoading] = useState(false);
const [error, setError] = useState<string | null>(null);

useEffect(() => {
  // you cannot open the dashboard without being logged in
  if (!authService.isLoggedIn()) {
    navigate("/login");
    return;
  }

  const fetchPosts = async () => {
    try {
      setLoading(true);
      const data = await postService.getMine();   // drafts included
      setPosts(data);
      setLoading(false);
    } catch (err) {
      setLoading(false);
      setError("Failed to load your posts");
    }
  };

  fetchPosts();
}, [navigate]);

In the header, show the user's initial and a sign out button:

<span>{user?.name.charAt(0).toUpperCase()}</span>
<button type="button" onClick={handleSignOut}>Sign out</button>

const handleSignOut = () => {
  authService.logout();
  navigate("/");
};

Check: logged out, /dashboard sends you to /login. Logged in, you see your initial and an empty list.

13.2 The stats

Don't call the api for these. Count the posts you already have:

const publishedCount = posts.filter((p) => p.status === "published").length;
const draftCount = posts.filter((p) => p.status === "draft").length;
// total = posts.length

13.3 The form state

This form has a file input and two submit buttons (Save draft / Publish), so we use plain useState here, not react-hook-form:

const [title, setTitle] = useState("");
const [slug, setSlug] = useState("");
const [tag, setTag] = useState("");
const [readTime, setReadTime] = useState("");
const [excerpt, setExcerpt] = useState("");
const [body, setBody] = useState("");
const [quote, setQuote] = useState("");
const [image, setImage] = useState<File | null>(null);

// when it is not null we are editing this post instead of creating a new one
const [editingId, setEditingId] = useState<string | null>(null);

Make every input controlled:

<input value={title} onChange={(e) => setTitle(e.target.value)} />
<textarea value={body} onChange={(e) => setBody(e.target.value)} />

The file input is different. It has no value. You read the file from e.target.files:

<input
  type="file"
  accept="image/*"
  onChange={(e) => setImage(e.target.files ? e.target.files[0]! : null)}
/>

13.4 Create a post (with FormData)

const buildFormData = (status: "published" | "draft") => {
  const data = new FormData();
  data.append("title", title);
  data.append("slug", slug);
  data.append("tag", tag || "Notes");
  data.append("readTime", readTime || "5 min");
  data.append("excerpt", excerpt);
  data.append("body", body);
  data.append("quote", quote);
  data.append("status", status);
  if (image) {
    data.append("image", image);   // "image" = the name in upload.single('image')
  }
  return data;
};

const resetForm = () => {
  setTitle(""); setSlug(""); setTag(""); setReadTime("");
  setExcerpt(""); setBody(""); setQuote(""); setImage(null);
  setEditingId(null);
};

const handleSave = async (status: "published" | "draft") => {
  try {
    const data = buildFormData(status);

    if (editingId) {
      const updated = await postService.update(editingId, data);
      setPosts((prev) => prev.map((p) => (p._id === editingId ? updated : p)));
    } else {
      const created = await postService.create(data);
      setPosts((prev) => [created, ...prev]);   // newest on top
    }

    Swal.fire({ position: "top-end", icon: "success",
                title: editingId ? "Post updated" : "Post saved",
                showConfirmButton: false, timer: 1500 });
    resetForm();
  } catch (err: any) {
    Swal.fire({ icon: "error", title: "Could not save the post",
                text: err.response?.data?.error || "Something went wrong" });
  }
};

The two buttons must be type="button", otherwise the browser submits the form and reloads the page:

<button type="button" onClick={() => handleSave("draft")}>Save draft</button>
<button type="button" onClick={() => handleSave("published")}>Publish</button>

We update posts with the answer of the api, without fetching again. That is the same trick as in the notes manager.

Check: publish a post with an image. It appears in the list, the image is in backend/uploads/posts/, and the post shows on Home and Articles. Save a draft. It shows in the dashboard but not on Home.

13.5 Edit a post

Clicking Edit fills the form and remembers the id:

const handleEdit = (post: Post) => {
  setTitle(post.title);
  setSlug(post.slug);
  setTag(post.tag);
  setReadTime(post.readTime);
  setExcerpt(post.excerpt);
  setBody(post.body);
  setQuote(post.quote || "");
  setImage(null);             // keep the old image unless a new one is picked
  setEditingId(post._id);
  window.scrollTo(0, 0);
};

handleSave already knows what to do when editingId is set. Add a Cancel button (onClick={resetForm}) that only shows while editing: {editingId && <button ...>Cancel</button>}.

13.6 Delete a post

Always ask before deleting:

const handleDelete = async (id: string) => {
  Swal.fire({
    title: "Are you sure?",
    text: "You won't be able to revert this!",
    icon: "warning",
    showCancelButton: true,
    confirmButtonColor: "#7C5CFF",
    cancelButtonColor: "#EC4899",
    confirmButtonText: "Yes, delete it!",
  }).then(async (result) => {
    if (result.isConfirmed) {
      try {
        await postService.delete(id);
        setPosts((prev) => prev.filter((p) => p._id !== id));
      } catch (err) {
        setError("Failed to delete the post");
      }
    }
  });
};

And the list of posts:

{posts.map((post) => (
  <div key={post._id}>
    <h3>{post.title}</h3>
    <span>{post.status}</span>
    <p>{formatDate(post.createdAt)} &middot; {post.readTime} read</p>
    <button type="button" onClick={() => handleEdit(post)}>Edit</button>
    <button type="button" onClick={() => handleDelete(post._id)}>Delete</button>
  </div>
))}

Check: edit the title of a post and save. The new title shows everywhere. The url does not change, because the form sends the old slug back. Delete a post and it disappears from the list and from Home.

Step 14 — Final test, the whole story

Do this once, from the start, as a new visitor would:

  1. Log out. Home shows the published posts, and the header says Sign in.
  2. Register a second account, then sign in with it.
  3. The dashboard is empty. You only see your posts.
  4. Publish one post and save one draft. Only the published one is on Home.
  5. Open the published post: lede, paragraphs, quote, image, "Read next".
  6. Edit it, then delete it.
  7. Sign out. Go to /dashboard by hand and you are sent back to /login.
  8. npm run build: no errors.

When something goes wrong

What you see Why it happens Fix
Network Error in the console backend not running, or wrong port start the backend; check baseURL in api.ts
CORS error app.use(cors()) missing it is in backend/src/app.ts, don't remove it
401 No token provided not logged in, or the interceptor is missing sign in again; check api.ts
403 on edit/delete the post belongs to another user normal: that is the backend protecting it
image does not show the url is missing the host, or has /api use imageUrl(post.image)
req.body is empty on create you set Content-Type yourself let axios set it for FormData
400 with a zod message a field breaks a backend rule (excerpt < 10 chars, body < 20…) read err.response.data; match the limits in post.schema.ts
article page shows the old post useEffect has [] instead of [slug] add slug to the array
the page reloads on Save the button is type="submit" by default use type="button"
