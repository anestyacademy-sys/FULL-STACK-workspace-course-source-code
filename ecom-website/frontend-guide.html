Bring the Kiosk frontend to life, step by step

The design template is already in your React pages: every header, card, form and footer is there as JSX and Tailwind classes. This guide covers what makes those pages work: TypeScript types, an API layer, routing, login, forms, image upload and live data from the backend.

Every code block comes from the real frontend/src folder. For the pages, the guide shows the logic (state, effects, handlers) and the JSX lines that use it. The long Tailwind classes are shortened to className="…" so you can see the logic.

Do the backend guide first. The API must be running on http://localhost:5000.

Phase 2

The data layer

Describe the JSON the backend sends. Then TypeScript can autocomplete listing.title and warn you about typos.

// The seller is populated by the backend, so userId comes back as an object
export interface Seller {
    _id: string;
    name: string;
    phone: string;
    createdAt: string;
}

export interface Listing {
    _id: string;
    title: string;
    price: number;
    category: string;
    place: string;
    description: string;
    image?: string | null;
    status: 'Live' | 'Paused' | 'Sold';
    views: number;
    userId: Seller;
    createdAt: string;
    updatedAt: string;
}
export interface User {
    _id: string;
    name: string;
    email: string;
    phone: string;
    createdAt: string;
}

export interface LoginResponse {
    user: User;
    token: string;
}
  • userId is typed as a Seller object, not a string, because the backend calls .populate('userId', 'name phone createdAt').
  • Dates are string because JSON has no date type. MongoDB dates arrive as "2026-09-22T10:00:00.000Z".
  • status is a union of the three allowed values, the same as the backend's STATUSES.

Use the same list as the backend's CATEGORIES. If you send any other value, the API returns 400 "invalid category".

// The six categories of the design. The backend accepts exactly these.
export const CATEGORIES = ["Cars", "Electronics", "Rentals", "Jobs", "Furniture", "Phones"];

// the header strip adds "All" in front, to clear the filter
export const FILTERS = ["All", ...CATEGORIES];

One configured axios instance: the base URL is written once, and the token is added to every request automatically.

import axios from "axios";

const api = axios.create({
    baseURL: 'http://localhost:5000/api',
    timeout: 10000
})


// before every request, add the token if the user is logged in
api.interceptors.request.use((config)=>{

    const token = localStorage.getItem('token');

    if(token){
        config.headers.Authorization = `Bearer ${token}`;
    }

    return config;
})


export default api;
  • Thanks to baseURL, services write api.get('/listings/list') instead of the full URL.
  • The request interceptor runs before every request. It reads the token saved at login and sets Authorization: Bearer …, the header the backend's authenticate middleware expects.
  • timeout: 10000 gives up after 10 seconds instead of waiting forever.

Everything about the logged-in user is in one object: register, login, logout and "who is logged in?".

import api from "./api";
import type { User, LoginResponse } from "../types/User";


export const authService = {

    // the backend logs you in straight away, so we save the token here too
    register: async ( data: { name: string, email: string, phone: string, password: string } ) : Promise<LoginResponse> =>{

        const response = await api.post('/users/register', data);
        const result: LoginResponse = response.data.data;

        localStorage.setItem('token', result.token);
        localStorage.setItem('user', JSON.stringify(result.user));

        return result;
    },

    login: async ( data: { email: string, password: string } ) : Promise<LoginResponse> =>{

        const response = await api.post('/users/login', data);
        const result: LoginResponse = response.data.data;

        // keep the token and the user in the browser
        localStorage.setItem('token', result.token);
        localStorage.setItem('user', JSON.stringify(result.user));

        return result;
    },

    logout: () : void =>{
        localStorage.removeItem('token');
        localStorage.removeItem('user');
    },

    // the user saved at login, or null when nobody is logged in
    getCurrentUser: () : User | null =>{
        const user = localStorage.getItem('user');
        return user ? JSON.parse(user) : null;
    },

    isLoggedIn: () : boolean =>{
        return localStorage.getItem('token') !== null;
    }

}
  • The backend wraps everything in { success, data, message }, and axios wraps that in its own response.data. That is why you read response.data.data.
  • The token and the user are saved in localStorage, so you stay logged in after a page refresh.
  • localStorage only stores strings. Use JSON.stringify to save the user and JSON.parse to read it back.

One function per backend endpoint. Pages never need to know the URLs.

import api from "./api";
import type { Listing } from "../types/Listing";


export const listingService = {

    // every listing. the three filters are optional:
    // cat  -> 'Cars', 'Phones' ... ( 'All' or nothing shows everything )
    // q    -> a word to look for in the title
    // sort -> 'newest' | 'price_asc' | 'price_desc'
    getAll: async ( filters?: { cat?: string, q?: string, sort?: string } ) : Promise<Listing[]> =>{
        const response = await api.get('/listings/list', { params: filters });
        return response.data.data;
    },

    // one listing, for the detail page. this also adds +1 to its views
    getById: async (id: string) : Promise<Listing> =>{
        const response = await api.get('/listings/byid/' + id);
        return response.data.data;
    },

    // the listings of the logged in user, whatever their status
    getMine: async () : Promise<Listing[]> =>{
        const response = await api.get('/listings/mine');
        return response.data.data;
    },

    // we send FormData because a listing can have a photo
    create: async (data: FormData) : Promise<Listing> =>{
        const response = await api.post('/listings/create', data);
        return response.data.data;
    },

    update: async (id: string, data: { status?: string, title?: string, price?: number }) : Promise<Listing> =>{
        const response = await api.put('/listings/edit/' + id, data);
        return response.data.data;
    },

    delete: async (id: string) : Promise<void> =>{
        await api.delete('/listings/delete/' + id);
    }

}
  • { params: filters } lets axios build the query string for you: { cat: 'Cars', sort: 'price_asc' } becomes ?cat=Cars&sort=price_asc. Axios also encodes special characters.
  • create takes a FormData, not an object, because a photo cannot travel inside JSON. Axios sets the multipart/form-data header itself.
  • You do not pass the token anywhere: the interceptor in api.ts adds it.

Small formatting functions that several pages share.

// Small helpers used by the pages, so we do not repeat them everywhere.

// 480000  ->  "₹4,80,000"    ( en-IN puts the commas the indian way )
export const formatPrice = (price: number) : string =>{
    return '₹' + price.toLocaleString('en-IN');
}

// "2026-09-22T10:00:00.000Z"  ->  "2 hours ago"
export const timeAgo = (date: string) : string =>{

    const seconds = ( Date.now() - new Date(date).getTime() ) / 1000;

    const minutes = Math.floor(seconds / 60);
    const hours = Math.floor(minutes / 60);
    const days = Math.floor(hours / 24);

    if(minutes < 1)  return 'just now';
    if(minutes < 60) return minutes === 1 ? '1 minute ago' : minutes + ' minutes ago';
    if(hours < 24)   return hours === 1 ? '1 hour ago' : hours + ' hours ago';
    if(days === 1)   return 'yesterday';

    return days + ' days ago';
}

// "2023-04-01T..."  ->  "2023"
export const yearOf = (date: string) : string =>{
    return new Date(date).getFullYear().toString();
}

// the backend gives "/uploads/listings/listing-123.jpg", the browser needs the full url
export const imageUrl = (image?: string | null) : string | null =>{
    return image ? 'http://localhost:5000' + image : null;
}

imageUrl matters most here. The database stores /uploads/listings/…jpg, but that file is on the backend server (port 5000), not on Vite (port 5173).

:id is a URL parameter. For /listing/66f1a…, the detail page reads 66f1a… with useParams().

Why the template uses Link, not <a href>

A Link changes the page without reloading the browser, so React keeps its state and the new page appears instantly. Use <a href> only for links that leave the app, such as tel: or another website.

<Link to={item === "All" ? "/search" : "/search?cat=" + item} className="…">
  {item}
</Link>

Phase 4

Accounts: sign up, sign in, sign out

Turn the template's static form into a validated form that logs the user in.

import { useState, type FormEvent } from "react";
import { Link, useNavigate } from "react-router-dom";
import { useForm } from "react-hook-form";
import { zodResolver } from "@hookform/resolvers/zod";
import { z } from "zod";
import Swal from "sweetalert2";
import { authService } from "../services/authService";

// the rules of the form
const signInSchema = z.object({
  email: z.string().email("invalid email"),
  password: z.string().min(6, "password must contain at least 6 characters"),
});

type SignInForm = z.infer<typeof signInSchema>;

// Sign in: react-hook-form + zod, exactly like the forms lesson.
function SignIn() {
  const navigate = useNavigate();
  const user = authService.getCurrentUser();
  const [query, setQuery] = useState("");

  const {
    register,
    handleSubmit,
    formState: { errors, isSubmitting },
  } = useForm<SignInForm>({ resolver: zodResolver(signInSchema) });

  const onSubmit = async (data: SignInForm) => {
    try {
      await authService.login(data);

      Swal.fire({
        position: "top-end",
        icon: "success",
        title: "Welcome back !",
        showConfirmButton: false,
        timer: 1500,
      });

      navigate("/dashboard");
    } catch (err: any) {
      Swal.fire({
        icon: "error",
        title: "Could not sign in",
        text: err.response?.data?.error || "Something went wrong",
      });
      console.log(err);
    }
  };

  const handleSearch = (e: FormEvent) => {
    e.preventDefault();
    navigate("/search?q=" + query);
  };

  const handleSignOut = () => {
    authService.logout();
    navigate("/");
  };

  return (
    // ... the template JSX, see below ...
  );
}

Now connect the template's form to it. Three changes: onSubmit on the form, {...register("name")} on each input, and an error line under each input.

<form onSubmit={handleSubmit(onSubmit)} className="…">
  <label className="…">
    Email
    <input type="email" placeholder="you@example.com" {...register("email")} className="…" />
    {errors.email && (
      <span className="text-[13px] text-[#C2410C]">{errors.email.message}</span>
    )}
  </label>

  <label className="…">
    Password
    <input type="password" placeholder="••••••••" {...register("password")} className="…" />
    {errors.password && (
      <span className="text-[13px] text-[#C2410C]">{errors.password.message}</span>
    )}
  </label>

  <button type="submit" disabled={isSubmitting} className="…">
    {isSubmitting ? "Signing in ..." : "Sign in"}
  </button>
</form>
  • {...register("email")} gives the input its name, onChange, onBlur and ref. You do not need useState for the inputs.
  • handleSubmit(onSubmit) runs the zod rules first. onSubmit is called only when the data is valid, and it receives typed data.
  • isSubmitting is true while the async onSubmit runs. Use it to disable the button so the form cannot be sent twice.
  • err.response?.data?.error shows the backend's message, for example "Invalid email or password".

This is the pattern you will reuse everywhere: state → useEffect fetch → loading / error / empty → map to cards.

  • The empty array [] at the end of useEffect means "run once, when the page opens".
  • You cannot make the useEffect callback itself async. Define an async function inside it and call that function.
  • key={item._id} helps React track each card. Use the database id, not the array index.
  • Values like fresh and countOf() are calculated from listings on every render. They do not need their own state.
  • When there is no photo, show the template's placeholder-fill block instead.

Keep the category and the search text in the URL (/search?cat=Cars&q=swift). Then a refresh, the back button or a shared link all show the same results.

import { useEffect, useState, type FormEvent } from "react";
import { Link, useNavigate, useSearchParams } from "react-router-dom";
import type { Listing } from "../types/Listing";
import { listingService } from "../services/listingService";
import { authService } from "../services/authService";
import { formatPrice, timeAgo, imageUrl } from "../services/helpers";
import { FILTERS } from "../data/categories";

// The results grid. The filter lives in the url ( /search?cat=Cars&q=swift )
// so it survives a refresh, and the backend does the filtering and the sorting.
function Results() {
  const navigate = useNavigate();
  const user = authService.getCurrentUser();
  const [searchParams] = useSearchParams();

  // the two filters come from the url
  const cat = searchParams.get("cat") || "All";
  const q = searchParams.get("q") || "";

  const [sort, setSort] = useState("newest");
  const [listings, setListings] = useState<Listing[]>([]);
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState<string | null>(null);
  const [query, setQuery] = useState(q);

  // this runs again every time the category, the search or the sort changes
  useEffect(() => {
    const fetchListings = async () => {
      try {
        setLoading(true);
        const data = await listingService.getAll({ cat, q, sort });
        setListings(data);
        setLoading(false);
      } catch (err) {
        setLoading(false);
        setError("Failed to load the listings");
        console.log(err);
      }
    };

    fetchListings();
  }, [cat, q, sort]);

  const handleSearch = (e: FormEvent) => {
    e.preventDefault();
    navigate("/search?q=" + query);
  };

  const handleSignOut = () => {
    authService.logout();
    navigate("/");
  };

  const sorts = [
    { key: "newest", label: "Newest" },
    { key: "price_asc", label: "Price low" },
    { key: "price_desc", label: "Price high" },
